## 2. Текущая структура инструмента

| Часть | Файлы | Что делает |
|---|---|---|
| Точка входа | `src/Program.cs` | запускает `MainForm` |
| Модель | `src/Model/BlockDef.cs`, `BuildingDef.cs`, `MapLayer.cs`, `ToolMode.cs` | описание блока (id, цвет, символ), здание, слой = `Dictionary<Point,string>` + стеки undo/redo, режимы инструмента |
| Холст | `src/Canvas/CanvasControl.*.cs` (8 partial, 1760 строк) | один класс `Control` содержит всё: данные трёх слоёв, каталог блоков, редактирование, undo, заливку, рендер, импорт и экспорт JSON, здания |
| Формы | `src/Forms/MainForm.*.cs` (5 partial, 806 строк) | две вкладки (глобальная 21 x 15 и локальная 1000 x 1000), каждая со своим `CanvasControl`; файлы, хоткеи, сайдбар |
| Тесты | `tests/Tests.cs`, `tests/BuildingTests.cs`, `tests/ImportProbe.cs` | самописные exe-раннеры без фреймворка; ImportProbe прогоняет 32 базы из `tests/legacy_bases` |
| Сборка | `build.cmd` | `csc.exe` из .NET Framework 4 (C# 5), WinForms, `System.Web.Extensions` (JavaScriptSerializer) |

Хранение слоёв. Три независимых словаря в `CanvasControl`: `_politicalLayer`, `_landscapeLayer`, `_objectLayer`. Ключ - `Point`, значение - строковый id блока (`color_RRGGBB`, `stone_wall`, `settlement_*`, `building_*`). Объектом считается блок с непустым `Symbol`, он всегда пишется в слой objects. Undo/redo хранится отдельно у каждого слоя, глубина не ограничена.

Чтение (`ImportJson`). JavaScriptSerializer разбирает файл в `Dictionary<string,object>`. Проверяются format, map_kind и map_size, есть поддержка старого формата с `global_map.editor_offset`. Каждый слой декодируется через `TryDecodeCells`. Метки, найденные в цветовых слоях, переносятся в objects. Затем валидируются здания, и только после этого всё применяется. Атомарность применения в памяти соблюдена.

Запись (`ExportJson`). Ручная сборка строки через StringBuilder: format, map_kind, map_size, created_at = текущее UTC, total_blocks, active_layer, visibility, layers{political, landscape, objects}, необязательный buildings, `blocks` = копия **активного** слоя. На диск пишется `File.WriteAllText(..., Encoding.UTF8)`, напрямую, без временного файла.

## 3. Где смысл определяется по одному hex или по имени

В коде нет ни одного места, где hex переводится в смысл (ландшафт или государство). Смысл живёт **вне данных**, и это хуже:

| # | Место | Что происходит |
|---|---|---|
| 1 | данные: политическая карта и файл диких земель | государства нарисованы на слое `landscape`, слой `political` пуст. Смысл "это политика" есть только в имени файла и в голове автора |
| 2 | данные: CC751E, 51CC51, 106B10 | в `nature.json` это пески, равнины, лес; в политической карте - Ультерия, Аскелия, Каннарария. Цвета совпадают полностью, отличить по содержимому нельзя |
| 3 | данные: `settlement_city` в файле диких земель | 4 штуки, это армии, а не города. Смысл задаёт только имя файла |
| 4 | данные: `settlement_village` в файле диких земель | 38 заготовок. По id не отличить от настоящих деревень политической карты |
| 5 | `CanvasControl.Catalog.cs`, `GlobalLandRows` | зашитая маска суши 21 x 15 из букв R, Y, G, M, B, C. Сверка с данными показала: это **старое политическое деление**. R = Рейнгард (34), B = Ортенверг (24), G = Ультерия (15), Y = Розенвальд + Аскелия + Каннарария (37), C = Гирденбург + Вальден (9), M = все дикие земли (65). Буквы нигде не используются, кроме проверки "суша / не суша", но маска определяет, какую клетку вообще можно открыть |
| 6 | `CanvasControl.Serialization.cs`, старый формат | слой назначения угадывается по ключу первой клетки `global_map.cells[0]`: `marker` значит политика, `nature_marker` значит ландшафт |
| 7 | `MainForm.Files.cs`, `OpenJsonFromFile` | тип карты (глобальная или локальная) определяется регэкспом по тексту файла |
| 8 | `TryDecodeCells` | допустимость блока определяется по префиксу строки: `building_` запрещён на глобальной карте, `settlement_` на локальной |
| 9 | `IsObject` | "это объект" значит "у блока непустой Symbol", то есть смысл выводится из свойства отображения |

Вывод для WorldStudio: семантика карты при импорте старого файла не выводится, а **выбирается автором явно** (ландшафт, политика или дикие земли). Валидатор подстраховывает: при неверном выборе почти наверняка появятся неизвестные цвета (383838 нет в политической легенде, CC1E1E нет в ландшафтной), и это проверка 1, [CRITICAL].

## 4. Сверка данных с промптом

Подтверждено:
- суша: 184 клетки во всех трёх файлах, набор координат совпадает с маской `GlobalLandRows`;
- ландшафт: равнины 51CC51 - 96, лес 106B10 - 37, пески CC751E - 34, горы - 17 (383838 - 16 и `stone_wall` - 1, клетка 14,9);

Ответ автора ("коричневые клетки - независимые, без официального лорда") с данными не конфликтует: владельца клетки задаёт этот общий слой;
- дикие земли: 6B3D10 - 30, 6B5845 - 20, 6B4A2A - 15; пятна по 4-связности: западное 28, южное 27, восточное 10 (только 6B3D10);
- метки: Д - 38, Г - 4, все стоят на коричневых клетках. Г на (4,6), (4,9), (12,11), (16,5): две в западном пятне, одна в южном, одна в восточном. Это совпадает с маршрутами из 5.5;
- 184 + 42 = 226 = total_blocks; 184 + 102 = 286 = total_blocks;
- поселения по государствам совпадают с таблицей 5.6 по всем 8 государствам: замки, города (вместе с крепостями) и деревни. Ультерия: на карте 3 города (2 city + 1 fortress), в таблице автора 4. Это известное расхождение, валидатор его покажет;
- каждое государство - одна связная область. Группы диких земель разорваны: 6B3D10 на 3 части, 6B5845 и 6B4A2A на 2 части каждая (проверка 9, [INFO]).

Деревни считаются с кратностью: village_2 = 2, village_3 = 3. Только при таком подсчёте числа совпадают с таблицей автора, так что трактовка "две деревни" подтверждена данными. В старом инструменте подпись другая - "Деревня, уровень 2" (OBSERVATIONS O-03).

## 6. План этапов

Ниже выбранный вариант (DECISIONS D-01, D-02, D-03). Новое решение `WorldStudio` лежит рядом с кодом PixelBuilder, а сам PixelBuilder не трогаю. Код собирается в две сборки:
- `WorldStudio.Core.dll` (Domain, Serialization, Validation, Application) компилируется **без ссылки на WinForms**, поэтому правило "никакого UI в домене" держит компилятор;
- `WorldStudio.exe` (UI).

Язык C# 5, компилятор `csc` .NET Framework 4, как у PixelBuilder: на твоей машине уже собирается, ничего ставить не нужно. Тесты гоняю в контейнере на mono (`mcs -langversion:5`), на Windows проверка через `build.cmd test`.

```
WorldStudio/
  build.cmd
  data/       legend.json, settlements_reference.json
  src/Core/   Domain/ Serialization/ Validation/ Application/
  src/UI/
  tests/      Tests.cs + fixtures (копии трёх карт)
  docs/       DECISIONS.md OPEN_ITEMS.md OBSERVATIONS.md REPORT_*.md
```
