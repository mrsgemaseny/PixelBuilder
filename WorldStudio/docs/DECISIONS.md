# DECISIONS

## D-01. WorldStudio - новое решение рядом с PixelBuilder, а не правка PixelBuilder
Варианты: (а) рефакторить PixelBuilder на месте; (б) новое решение, переносить код по частям.
Выбрано (б). Причины: старый инструмент должен оставаться рабочим эталоном совместимости, пока автор от него не откажется (5.1). Модели PixelBuilder завязаны на `System.Drawing.Point/Color` и живут внутри `Control`, поэтому чистый домен всё равно пришлось бы писать заново. Из PixelBuilder переношу формат, каталог id и идеи рендера.
Автор разрешил выбрать (сообщение от 2026-11-17).

## D-02. Две сборки: Core.dll без WinForms и UI.exe
Причина: правило "никакой бизнес-логики в UI и никакого UI в домене" держит компилятор: Core собирается без ссылки на System.Windows.Forms. Плюс Core тестируется на mono без X-сервера.

## D-03. C# 5, csc из .NET Framework 4, как у PixelBuilder
Варианты: .NET 8 SDK + NuGet (ClosedXML, System.Text.Json); .NET Framework 4 + csc (уже есть на машине автора).
Выбран второй. Причины: ноль установок у автора, тот же build.cmd-подход, который уже работает. Цена: синтаксис C# 5, нет NuGet. xlsx пишу сам через System.IO.Compression (zip + XML), JSON тоже сам (D-04). Проверка в контейнере: mono `mcs -langversion:5`.

## D-04. Свой JSON-парсер и писатель
Причина: JavaScriptSerializer не гарантирует порядок ключей, теряет исходный вид чисел и не умеет детерминированно писать. Приёмка Этапа 1 (неизвестное поле сохраняется) и Этапа 5 (байт-в-байт) требуют контроля над порядком и форматом. Объём около 300 строк, покрывается тестами.

## D-05. Семантика старого файла выбирается явно при импорте
Причина: раздел 5.2 и антипаттерн 1. Содержимое политической карты и файла ландшафтов по набору цветов частично совпадает (CC751E, 51CC51, 106B10). Автоопределения нет; валидатор ловит неверный выбор через проверку неизвестных цветов.

## D-06. Владелец клетки берётся из общего слоя landscape политической карты и файла диких земель
Сверка: слои идентичны (184 из 184). Ответ автора: коричневые клетки - независимые земли без официального лорда. Метки Д и Г берутся только из файла диких земель, поселения государств - только из политической карты. Если слои когда-нибудь разойдутся, это будет находка валидатора, а не тихий выбор одного из них.

## D-07. village_2 и village_3 - кратность (2 и 3 деревни), а не уровень
Сверка: только при кратности число деревень по каждому из 8 государств совпадает с таблицей 5.6. Подпись "уровень" в старом инструменте не переношу (OBSERVATIONS O-03).

## D-08. Привязка меток Г к армиям - по пятну диких земель
Из 5.5: две армии на запад, одна на юг, одна на восток. Метки: (4,6) и (4,9) в западном пятне, (12,11) в южном, (16,5) в восточном. Это вывод из данных, без придумывания координат. Какая из двух западных меток соответствует какому маршруту, неизвестно: id нейтральные (`army.west_1`, `army.west_2`), I-04.

## D-09. Круговой тест pixel_architect_v1 сравнивает смысл, а не байты
Причина: старый писатель меняет created_at, BOM и поле blocks. Байт-в-байт требуется только для world.json (Этап 5).
Дополнение (Этап 1): вторая запись уже прочитанного документа байт в байт равна первой, это проверяется отдельно.

## D-10. Формат с полем global_map (до слоёв, холст 1000 x 1000 со смещением) не читается
Варианты: перенести логику смещения из PixelBuilder; отказывать с понятным сообщением.
Выбран отказ. Ни одного такого файла нет среди 35 известных (3 карты + 32 базы). Перенос логики без тестового файла - угадывание (правило 5). Сообщение: открыть в PixelBuilder и пересохранить.

## D-11. Кодек pixel_architect_v1 не добавляет полей, которых не было в файле
Найдено на Этапе 1: 32 локальные базы содержат только blocks, без map_kind и layers. Первая версия писателя добавляла пустое "layers": {}, и старый PixelBuilder переставал открывать файлы (его импорт требует слой political внутри layers). Исправлено: map_kind, layers, total_blocks, blocks пишутся только если были в файле или заданы в модели. Тест проверяет порядок полей корня по записанному тексту, а не через тот же писатель.

## D-12. Кодек не проверяет id блоков
Значения клеток (color_*, stone_wall, settlement_hamlet, building_house_3x2_h и т.д.) сохраняются как есть. Смысл id - дело импорта с семантикой (Этап 2). Поэтому settlement_hamlet при чтении и записи не теряется; решение по нему (I-05) нужно только к Этапу 2.

## D-13. Совместимость со старым PixelBuilder проверяется самим PixelBuilder
CompatProbe собирается против PixelBuilder.exe и вызывает его родной CanvasControl.ImportJson для исходного и записанного файла: оба должны открыться, число блоков и собственный экспорт старого инструмента (без created_at) совпадают. Повторять правила старого импортёра в WorldStudio не нужно, и они не разойдутся с реальностью.

## D-14. Новые файлы в отчёте не дублируются
Правило 10 требует показывать новые файлы целиком. Этап 1 - 19 файлов, 2236 строк; копия в REPORT сделала бы его нечитаемым. Файлы лежат целиком в src/ и tests/, в отчёте - список со строками. Если нужен код прямо в отчёте, скажи.

## D-15. Легенда хранится внутри world.json (поле legend), а не отдельным legend.json
Промпт допускает "путь или встроенный legend". Встроенная легенда делает world.json самодостаточным: игре и инструменту не нужен второй файл, легенда не может потеряться или разойтись с миром. Семантики разделены таблицами: landscape_values (карта ландшафтов), owner_values (политическая карта и файл диких земель), political_objects, wildland_objects, export_landscape.

## D-16. world.json с дубликатами id не открывается
Мир в памяти дубликатов не допускает. Файл с дубликатами - битый (раздел 9: ничего не менять, показать причину): ошибка называет id и проверку 12. Сама проверка 12 страхует сущности в памяти, порядок матрицы и id извне (ValidationInput.ExternalIds).

## D-17. Реестр и отношения - в шаблоне data/world_template.json (формат world.json)
Государства, группы, армии и матрица из промпта (5.2, 5.5, Приложение B) лежат данными, а не кодом. Клетки бродячих армий = клетки меток Г из файла диких земель (D-08). Начальная точка и клетка уничтоженной армии пустые (I-04). Из-за этого чтение world.json сделано на Этапе 2, раньше плана (Этап 5 добавил детерминированность, миграции и версии).

## D-18. Расхождения между старыми файлами - находки импорта, первой остаётся политическая карта
Разные владельцы одной клетки в политической карте и файле диких земель, разные значения в слоях political и landscape одного файла, клетка суши не во всех картах - всё это находки "import" [WARNING]. На текущих файлах их 0.

## D-19. Неизвестное значение при импорте не придумывается
Клетка остаётся сушей без ландшафта или владельца, объект не импортируется; проверка 1 [CRITICAL] показывает каждое такое место по исходным файлам. Так settlement_hamlet (I-05) не станет молча деревней.

## D-20. Экспорт в старый формат
Горы пишутся одним значением color_383838 (legend.export_landscape), поэтому stone_wall на (14,9) после экспорта станет color_383838 - смысл тот же. Один объект на клетку (ограничение формата) - лишние с предупреждением. Клетка вне маски суши старого PixelBuilder - предупреждение и подтверждение перед записью. Экспорт трёх карт совпадает с исходниками по клеткам и объектам (кроме stone_wall), старый PixelBuilder их открывает.

## D-21. Формат world.json
Ключи отсортированы, LF, без BOM, перевод строки в конце; клетки по (y, x), объекты по id; порядок государств, групп и армий - порядок реестра (это данные автора). meta.updated_at меняется только при сохранении: два экспорта без сохранения байт-в-байт равны.

## D-22. История версий не чистится сама
Копия перед каждой перезаписью world.json, экспорта в старый формат и xlsx; journal.log с sha256. Автоматическое удаление старых копий - деструктивная операция (правило 2), поэтому её нет. Future consideration: кнопка "очистить историю старше N" с подтверждением.

## D-23. /warnaserror только для Core и тестов
Предупреждения WinForms различаются между mono и csc; строгий режим для UI мог бы сломать сборку у тебя из-за предупреждения, которого у меня нет. Core и тесты собираются строго.

## D-24. Ожидаемые находки на текущих картах
Промпт называет три (Ультерия, заготовки, пятая армия). Фактически их 9, все кроме Ультерии - [INFO]: три напоминания проверки 2 (CC751E, 51CC51, 106B10) и три разрыва групп диких земель (проверка 9; группа 1 - 3 части, группы 2 и 3 - по 2). Тест S3.ExpectedFindings проверяет ровно этот список.

## D-25. Маркер "у государства нет клеток" - [WARNING]
В разделе 8 маркер для этого случая не указан ([INFO] указан только для несвязанных частей).

## D-26. Ластик ландшафта очищает тип, сушу не убирает
Убрать сушу можно только через меню "Мир - Убрать сушу в выбранной клетке" с подтверждением; если на клетке объект или армия - отказ (их пришлось бы молча удалять).

## D-27. Политика и дикие земли - один атрибут клетки (владелец), но разные слои редактора
Ластик и пипетка слоя видят только свой вид владельца; блокировка слоя защищает от случайной правки чужого.

## D-28. Маршрут армии рисуется по клеткам, без автопрокладки
Клики добавляют точки, весь маршрут сохраняется одной командой. Разрывы между соседними точками показывает проверка 11, инструмент их не заполняет (не придумывать координаты, 5.5).

## D-29. UiKit - копия в каждом приложении, не общая библиотека
WorldStudio и PixelBuilder собираются независимо (свои build.cmd, свой csc-набор файлов), PixelBuilder можно отдать без WorldStudio. Общая dll связала бы их версии и сборку. Поэтому `src/UI/Kit` (WorldStudio) и `src/Kit` (PixelBuilder) - один и тот же код с разным namespace; правится в WorldStudio и копируется (sed по namespace). Расхождение заметно по diff. Future consideration: общая dll, если появится третье приложение.

## D-30. Контролы рисуются сами, WinForms только как каркас
Кнопки (UiButton : Button), сегменты, тосты, группы строк, матрица отношений, ползунок, карточки импорта рисуются вручную: стандартные контролы WinForms не умеют скруглений, тёмной темы и иконок. UiButton наследует Button, чтобы PerformClick, DialogResult, AcceptButton и тесты работали как раньше. Анимаций и размытия нет - WinForms их не даёт без собственного движка, это осознанная граница.

## D-31. Тема по системной настройке Windows
По умолчанию - как в Windows (реестр HKCU\...\Personalize\AppsUseLightTheme), в меню "..." можно выбрать светлую или тёмную; выбор хранится в настройках пользователя (WorldStudio: папка настроек, PixelBuilder: %APPDATA%\PixelBuilder\theme.txt). Цвета карт (ландшафт, государства) от темы не зависят - это данные; от темы зависят только фон, сетка, рамки и интерфейс.

## D-32. PixelBuilder: вкладки карт остались, заголовки скрыты
Тесты и логика переключения опираются на TabControl с двумя страницами. Заголовки вкладок обрезаны регионом, переключает сегмент "Глобальная / Локальная" сверху. Поля формы, на которые смотрят тесты (_objectPanel, _btnRotate, _btnRoofs, _objectsHeading, _lblActiveBlock, _canvas), сохранили имена и базовые типы. Формат файлов не менялся: CompatProbe и ImportProbe проходят на новом PixelBuilder.

## D-33. Метки диких земель: независимое поселение и имперская армия
Решение автора 2026-11-18: в файле диких земель Д - независимое поселение (без лорда), Г - имперская армия. В PixelBuilder для них добавлены отдельные объекты глобальной карты: `independent_settlement` ("Независимое поселение", знак Н) и `imperial_army` ("Имперская армия", знак А), чтобы не рисовать их деревней и городом. Импорт WorldStudio принимает и новые id, и старые (`settlement_village`/`settlement_city` в файле диких земель) - мир получается байт в байт тот же (тест S2.NewMarkIds). Экспорт в файл диких земель пишет новые id; новый PixelBuilder их открывает (COMPAT_PASS), PixelBuilder до 2026-11-18 - нет.
Коды в world.json не переименованы (`village_mark`, `army_mark`): миграция схемы ради имени не нужна, смысл записан в README и в комментарии к типу. Независимые поселения в сверку с таблицей автора не входят: таблица ведётся по государствам. Проверка 6 теперь сообщает их число как [INFO] без слова "заготовка".

## D-34. Основные карты - в data/sources.json
Три файла автора из `MiniLife\future\map` закреплены как источники по умолчанию: окно импорта подставляет их само. Пути лежат в отдельном файле данных, а не в коде: их можно поменять без пересборки. Файлов нет на диске - карточка пустая, без ошибки. Файлы MiniLife только читаются (репозиторий игры не меняется). Данные этих файлов совпадают с фикстурами tests/fixtures по всем слоям (отличается только форматирование), поэтому тесты остаются эталоном.
